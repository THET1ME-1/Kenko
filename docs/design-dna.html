ДНК Kenko

Разбор дизайн-системы приложения Kenko (GPL-3.0, LooKeR & Contributors) перед тем, как дописывать в форк программы, суперсеты, дропсеты и таймер. Всё ниже снято с кода ветки main, коммит bdcfd73: цвета из ui/theme/colorSchemes, размеры из Shapes.kt и Type.kt, отступы из вёрстки экранов.

Система держится на трёх решениях: гротеск против моноширинного, линия вместо тени и крупная типографика вместо картинок. Новые экраны должны повторять их, иначе форк расслоится на «их» и «наше».

01 Шрифт

Два семейства и ни одного больше. Darker Grotesque — плотный гротеск с высокой строчной, работает на крупных кеглях. Space Mono — моноширинный, держит цифры в столбик и задаёт «журнальный» характер интерфейса. Оба лежат в res/font/, за шрифтом в сеть приложение не ходит.

02 Цвет

Полный набор ролей Material 3 в четырёх готовых палитрах плюс динамическая с обоев Android 12+. По умолчанию включена Zestful: оливково-лаймовая, фон тёплый кремовый, а не белый. Свои цвета в коде не появляются нигде, кроме файлов палитр, — единственное исключение во всём проекте это JapanRed = #E03523 для иконки.

Новый экран не имеет права упоминать hex: только MaterialTheme.colorScheme.*, иначе он выпадет из трёх палитр из четырёх.

03 Форма и линия

Скругления заданы своим набором, он мельче стокового Material: 4 · 8 · 14 · 20 · 28 dp. Плюс четыре расширения в Shapes.kt (top(), bottom(), start(), end()), которыми углу задают форму по одной стороне: так собираются списки, где у первого элемента скруглён верх, у последнего низ.

Линия вместо тени

Теней в приложении нет ни одной. Глубину дают три вещи: обводка KenkoBorderWidth = 1.4dp, ступень поверхности (surface → surfaceContainer → surfaceContainerHigh) и разделители HorizontalDivider(thickness = KenkoBorderWidth) той же толщины. Готовые кисти лежат в components/Border.kt: PrimaryBorder, SecondaryBorder, OutlineBorder, OnSurfaceBorder, OnSurfaceVariantBorder.

05 Как собран экран

Три повторяющихся приёма, по которым Kenko узнаётся с одного взгляда.

Приём 1

Пустота работает. На главной между разделителями стоят распорки weight(1F), заголовок в 78sp висит в середине, кнопка прижата к низу. Экран не заполняют карточками ради заполнения.

Приём 2

Число крупнее подписи. Номер подхода, счётчик упражнений, вес — набраны кеглем в два-три раза больше, чем их ярлыки. Подпись серая (outline), значение чёрное.

Приём 3

Разделитель как рамка. Секции разграничены линиями 1.4dp во всю ширину, а не отступами. Карточки живут внутри полосы, а не парят на фоне.

Навигация: Navigation 3, экраны перечислены в ui/navigation/Routes.kt, переходы описаны один раз в KenkoNavHost.kt (предиктивный назад, уход кадра масштабом 0.9). Верхняя панель у каждого экрана своя, общего TopAppBar нет: на главной это KenkoTopBar с кнопкой профиля.

06 Правила для нового кода

  • ✓Цвет только через MaterialTheme.colorScheme, размеры углов только через MaterialTheme.shapes.
  • ✓Числа — numbers(), заголовок-герой — MaterialTheme.typography.header() с LineBreak.Heading.
  • ✓Любая строка заводится в res/values/strings.xml и values-ru/strings.xml; остальные 35 переводов подтянут переводчики.
  • ✓Новая иконка — ic_*.xml в res/drawable плюс строка в KenkoIcons, контурная, штрих в тон существующим.
  • ✓Экран получает данные из ViewModel через collectAsStateWithLifecycle и имеет второй, приватный @Composable с параметрами по умолчанию — для превью.
  • ✕Тени, elevation, градиенты. Глубина — ступень поверхности и обводка 1.4dp.
  • ✕Третий шрифт, эмодзи в интерфейсе, hex прямо в вёрстке.
  • ✕Material-компоненты «из коробки» там, где уже есть свой кирпич: кнопка, чип, пустая страница, разделитель.

08 Что придётся строить с нуля

Чего в системе нет вообще, поэтому под это придётся заводить новые кирпичи, держась правил выше.

Нет в коде

Числовой ввод с клавиатуры. Вес и повторы вводятся перетаскиванием. Для замеров тела и калькулятора блинов понадобится поле ввода в этом же языке: моноширинное, с обводкой, без плавающей подписи Material.

Нет в коде

График по датам. Есть сетка активности (FrequencyGraph) и построитель сглаженной кривой по точкам (Plot.kt), но ни осей, ни подписей, ни выбора периода. Вес, объём и рекорды рисовать на канве штрихом с круглым концом, как Wave, библиотеку не подключать.

Нет в коде

Снимки. Ни одного Image из файла: приложение обходится вектором и типографикой. Фото замеров придётся вводить осторожно — скругление 20, обводка, без теней.

Нет в коде

Единицы веса. Строка KG вшита прямо в вёрстку дважды, обе в SetItem.kt (строки 99 и 148). Фунты потребуют настройку, ресурс строки и пересчёт.
